# Public Space completion

**우선순위 변경: 2026-09-26.** Public Space를 먼저 완성한다. 게임 개발·게임 기획 자기소개서에 활용할 수 있도록 작업의 문제, 선택, 구현, 검증을 읽을 수 있게 하되 실제 경험·성과·역할은 근거 없이 만들지 않는다.

## 현재 공개 내용

- Works: 기존 공개 갤러리의 실제 작품 1건. 서버는 기존 데이터 어댑터로 읽고 GitHub Pages는 공개 스냅샷을 사용한다.
- Projects: 저장소로 확인 가능한 Pluto Archive 제작 사례와 상세 페이지. 진행 중으로 표기한다.
- Process: 이 프로젝트의 정보 설계·원본 보존·검증을 실제 예시로 설명한다.
- About: 이미지·인터페이스·게임의 연결에 대한 관심을 희망 방향으로 서술하고 공개 작품·사례를 증거로 연결한다.
- Contact: 확인된 GitHub 프로필만 제공한다. 실제 연락 수단은 아직 제공받지 않았다.

## 다음 순서

1. 사용자와 함께 자기소개서에 사용할 **검증 가능한 개인 경험**을 정리한다: 목표 직무(게임 개발/기획/둘 다), 참여한 게임·팀 프로젝트, 본인 역할, 기획 문서·프로토타입·코드, 문제 해결, 검증 가능한 결과. 받은 자료에 맞춰 About과 사례 문구를 교정한다.
2. 실제 프로젝트가 있다면 목표→문제→역할→선택→제작→검증→배운 점 순서로 사례를 추가한다. 이미지·시연·저장소 링크의 공개 가능 여부를 확인한다. 없는 항목은 비워 두고 경험으로 포장하지 않는다.
3. Works의 작품 분류·Featured·상세 설명과 Projects/Process를 실제 콘텐츠로 확장한다. 기존 갤러리 데이터와 CMS 데이터의 공개 범위를 먼저 정합화한다.
4. 공개 콘텐츠를 CMS의 Draft→Preview→Publish 흐름으로 옮긴다. 이전 공개 gallery/Storage와 정적 스냅샷의 가시성 문제를 해결하고 나서 관리 UI를 공개한다.
5. 실제 연락 채널을 받아 Contact를 완성하고, 모바일 읽기·키보드 접근·메타데이터·이미지 대체 텍스트·실측 성능을 확인한다.

## 완료 기준

- 모든 공개 탐색 경로와 상세 링크가 Pages와 서버에서 동작한다.
- 자기소개 문구는 사용자가 확인한 사실과 희망 방향을 분리한다.
- 공개 프로젝트마다 본인 역할·근거 자료·현재 상태가 분명하다.
- 작품·프로젝트 등록/수정/게시가 실제 운영 흐름으로 연결되고 공개/비공개 상태가 양쪽 배포에서 일치한다.
- Contact에 실제 연락 경로가 있고 모바일·접근성·성능 검증을 마친다.

현재는 탐색과 첫 사례 구성 단계다. 개인 이력, 게시 CMS, 연락 경로가 없으므로 Public Space 완료로 표시하지 않는다.
